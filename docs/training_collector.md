# Отдельный мастер сбора датасета

`training` — самостоятельный модуль для ручной подготовки данных для YOLO
segmentation. Он не запускает производственный цикл и не меняет
`inspection/part_archive.py`, HMI или orchestrator. Использовать мастер нужно
при остановленной основной программе: отдельный процесс занимает камеры.

## Запуск

Из корня проекта Windows:

```bat
training.bat
```

Или напрямую:

```bat
.venv\Scripts\python.exe -m training --open-browser
```

По умолчанию веб-интерфейс доступен на `http://127.0.0.1:8010/`, данные
пишутся в `training_datasets/<имя партии>_<дата>_<идентификатор>/`. Параметры:

```text
--root training_datasets       корень наборов
--mapping camera_mapping.json  соответствие ролей и USB ID
--config training_config.json  список ролей и элементов палитры
--host 0.0.0.0 --port 8010
```

`training_config.example.json` можно скопировать в свой конфигурационный файл
и изменить список элементов палитры под конкретную модель.

## Рабочий процесс

1. Введите имя набора, элементы палитры и отметьте камеры. Порядок чекбоксов —
   порядок показа кадров. Примеры элементов: `contact`, `omission`.
2. Нажмите **Новая деталь**. Мастер снимает кадр только следующей камеры и
   сохраняет его с индивидуальным `image_id`.
3. В палитре выберите элемент. На текущем кадре кликайте вершины произвольного
   контура по очереди. После минимум трёх точек нажмите **Завершить область**;
   также область можно замкнуть кликом по первой точке или двойным кликом.
4. Можно выбрать другой элемент и добавить ещё один полигон на том же кадре.
   Поэтому один кадр может содержать несколько областей и классов. Кнопка
   **Очистить области** удаляет незавершённый контур и все сохранённые области
   текущего кадра. Если дефекта нет, нажмите **Дефекта нет**.
5. Кнопка **ГОТОВО** завершает разметку всего текущего кадра. После неё
   сохраняются оригинал и annotated-копия, затем нажмите **Следующая камера**.
6. После всех камер завершите деталь и начните следующую.
7. **Завершить набор** создаёт готовую структуру YOLO segmentation.

### Когда выполняется сохранение

Сохранение выполняется поэтапно, поэтому уже снятый оригинал не потеряется при
ошибке разметки или закрытии интерфейса:

- после съёмки камеры сразу записываются глобальный оригинал
  `images/frame_...jpg`, копия `details/part_.../*_original.jpg`, а также
  запись со статусом `pending` в `manifest.jsonl` и обновлённый `session.json`;
- после нажатия **ГОТОВО** оригинал не перезаписывается, а дополнительно
  создаются `annotated/...jpg`, `labels/...txt`, `*_annotated.jpg` и `*.txt` в
  папке детали; запись кадра получает статус `annotated`;
- после **ЗАВЕРШИТЬ ДЕТАЛЬ** в `session.json` фиксируется завершённая деталь и
  список её `image_id`;
- после **ЗАВЕРШИТЬ НАБОР** создаётся папка `yolo/`, копируются изображения и
  labels в `train`/`val`, записываются `dataset.yaml`, `classes.json`,
  `split.json`, а в `session.json` появляется `finished_at`.

Проверять сохранение можно по `manifest.jsonl`: в нём есть индивидуальный
`image_id`, камера, деталь, статус, пути оригинала/overlay/label и список
полигонов. Файл `session.json` содержит состояние сессии, камеры, палитру,
детали и `yolo_task`. Оригинал должен оставаться неизменным после разметки.

Для каждого кадра сохраняются глобальные файлы:

```text
images/frame_000001_TOP.jpg       оригинал без изменений
annotated/frame_000001_TOP.jpg   отдельная копия с полигонами и подписями
labels/frame_000001_TOP.txt      YOLO segmentation; для «дефекта нет» пустой
```

Кроме этого, внутри папки каждой детали создаётся понятная пара по каждой
камере:

```text
details/part_0001/
  TOP_original.jpg
  TOP_annotated.jpg
  TOP.txt
  INPUT_LEFT_original.jpg
  INPUT_LEFT_annotated.jpg
  INPUT_LEFT.txt
```

`*_original.jpg` никогда не содержит разметку. `*_annotated.jpg` содержит все
замкнутые контуры, нанесённые на данный кадр. Связь кадра с деталью и камерой
находится в `manifest.jsonl`. `frame_uid` включает имя партии и номер, поэтому
картинки можно однозначно сопоставить даже после копирования набора.

## Формат YOLO segmentation

Для каждого полигона label-файл содержит одну строку:

```text
class_id x1_norm y1_norm x2_norm y2_norm ... xN_norm yN_norm
```

`class_id` — индекс элемента в `classes.json`, а координаты вершин нормированы
на ширину и высоту изображения и записаны в порядке кликов оператора. Координаты
проверяются, ограничиваются размерами кадра, а полигон должен иметь минимум три
точки и ненулевую площадь. Старый API с `BoundingBox` по-прежнему принимается:
он экспортируется как четырёхточечный прямоугольный полигон.

После завершения партии:

```text
yolo/
  dataset.yaml
  classes.json
  split.json
  images/train/*.jpg
  images/val/*.jpg
  labels/train/*.txt
  labels/val/*.txt
```

Разбиение train/val выполняется **по деталям**, а не по кадрам: изображения
одной детали с разных камер не оказываются одновременно в обучении и проверке.
Для одной детали `val` в `dataset.yaml` указывает на `train`, потому что
искусственная копия не является честной валидацией.

Пример запуска Ultralytics после сбора:

```python
from ultralytics import YOLO

model = YOLO("weights/base.pt")
model.train(
    task="segment",
    data="training_datasets/my_set_.../yolo/dataset.yaml",
    epochs=50,
)
```

## Программный API

Без веб-интерфейса модуль можно использовать через `TrainingCollector`:

```python
from training import TrainingCollector, TrainingConfig

collector = TrainingCollector(config, frame_source=my_camera_source)
collector.start_session("contacts_may")
collector.begin_part()
frame = collector.capture_next()       # кадр одной камеры, image_id
collector.annotate_current(
    annotations=[
        {
            "class_name": "contact",
            "points": [
                {"x": 100, "y": 80},
                {"x": 240, "y": 70},
                {"x": 280, "y": 150},
                {"x": 130, "y": 180},
            ],
        },
        {
            "class_name": "omission",
            "points": [[420, 200], [500, 210], [480, 270]],
        },
    ],
)
# если дефектов нет: collector.skip_current()
# повторить capture_next/annotate_current для всех камер
collector.finish_part()
collector.finish_session()
```

Для совместимости с прежними интеграциями остаётся и старый вызов:

```python
collector.annotate_current(
    boxes=[{"class_name": "contact", "x": 100, "y": 80,
            "width": 140, "height": 90}],
)
```

`frame_source` должен иметь единственный метод
`capture_single(role) -> numpy.ndarray`. Для существующего `CameraManager`
можно использовать `CollectorCameraSource`. Камеры подключаются только к
этому мастеру, пока производственная программа остановлена.
