# Compact version

Новый каркас ConveyerSeven в отдельной папке. Цель — сохранить **полную функциональную совместимость** с текущим проектом, но переносить систему в компактную модульную архитектуру без больших файлов-оркестраторов.

> Текущий статус: **этап 1 — архитектурный каркас**. Он проверяет конфигурацию и фиксирует контракт совместимости, но намеренно не подключается к COM-порту, камерам и приводам. Движение оборудования из этой папки пока невозможно.

## Что уже готово

- самостоятельный Python-пакет `conveyor_compact` в `src/`;
- единый composition root `bootstrap.py` вместо сборки зависимостей по всему коду;
- узкие интерфейсы камер, инспекции, конвейера, распределителя, UI и архива в `ports.py`;
- lifecycle с запуском по порядку, обратным выключением и rollback при ошибке;
- перенесённая доменная логика категорий `GOOD / BAD / CLEANUP`;
- конечный автомат линии и проверка порядка фаз шага;
- строгая проверка четырёх совместимых JSON-конфигов;
- manifest камер, правил, фаз и существующих API-маршрутов;
- unit-тесты каркаса;
- копия совместимой прошивки `firmware/convey15.ino`.

## Структура

```text
compact_version/
├── src/conveyor_compact/
│   ├── bootstrap.py       создание приложения в одном месте
│   ├── compatibility.py   неизменяемый внешний контракт
│   ├── config.py          загрузка и валидация конфигурации
│   ├── ports.py           интерфейсы внешних подсистем
│   ├── lifecycle.py       запуск, rollback и shutdown
│   ├── domain/            деталь и состояние линии
│   └── production/        фазы производственного шага
├── tests/                 быстрые тесты без оборудования
├── firmware/              совместимая прошивка контроллера
├── *.json                 production-конфигурация прежнего формата
├── pyproject.toml
└── requirements.txt
```

Архитектура остаётся намеренно неглубокой. Новый подмодуль добавляется только тогда, когда у него появляется отдельная ответственность и тестируемый контракт.

## Проверка каркаса

Без установки тяжёлых CV-зависимостей:

```bash
cd compact_version
PYTHONPATH=src python -m conveyor_compact doctor --root .
PYTHONPATH=src python -m unittest discover -s tests -v
```

На Windows можно использовать:

```bat
run.bat
run_tests.bat
```

Для машинно-читаемого отчёта:

```bash
PYTHONPATH=src python -m conveyor_compact doctor --root . --json
PYTHONPATH=src python -m conveyor_compact manifest --json
```

## Правила дальнейшего переноса

1. **Поведение раньше реализации.** Роли 7 камер, 13 правил (включая `part_presence`), категории, фазы, JSON и API фиксируются compatibility-тестами.
2. **Fail closed.** Ошибка обязательной камеры, модели, COM-порта или правила блокирует production; безопасные fallback-координаты не добавляются.
3. **Один composition root.** Конкретные классы создаются только в `bootstrap.py`; production-логика работает через порты.
4. **Без монолитов.** Production-шаг разделяется на motion, capture, inspection, routing и publish-сервисы. UI-диагностика не смешивается с движением линии.
5. **Без скрытой миграции.** Пока адаптер не перенесён и не покрыт тестом, он отмечен `planned`, а production-запуск остаётся отключён.
6. **Прошивка и механика неизменны.** Маршруты остаются: GOOD=`DIST1 0`; BAD=`DIST2 0 → DIST1 340`; CLEANUP=`DIST2 340 → DIST1 340` с безопасным возвратом DIST1 в `0` перед перемещением DIST2.

## Полная установка в будущем

`requirements.txt` сохранён совместимым с основной версией. После переноса runtime-адаптеров окружение будет устанавливаться так:

```bat
setup.bat
```

Сейчас эта установка для `doctor` и unit-тестов не требуется.
