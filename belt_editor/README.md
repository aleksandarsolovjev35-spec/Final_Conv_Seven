# belt_editor — сборщик ленты (универсальный путь корпуса)

Первый шаг перевода линии на универсальную конфигурируемую систему:
экран, на котором **путь корпуса собирается вручную**, без захардкоженных
позиций. Никакого оборудования, Node.js или сборщиков — только браузер и
Python 3.11+ из стандартной библиотеки.

## Запуск

```bat
run_belt_editor.bat
```

или из консоли:

```bat
python belt_editor/serve.py --port 8020
```

Откроется `http://127.0.0.1:8020/`. Конфигурация сохраняется в
`belt_editor/belt_path.json`, черновик правок — в localStorage браузера.

Проверить конфигурацию без сервера:

```bat
python belt_editor/serve.py --validate belt_editor/belt_path.json
```

## Элементы сборки

| Элемент | Что делает |
|---|---|
| **Позиция** | слот ленты; корпус сдвигается на одну позицию за шаг |
| **Место инспекции** | добавляется на позицию и делает её инспекционной; содержит список камер (ролей) |
| **Основное место инспекции** | определяет наличие детали (`part_presence`) |
| **Точка сброса** | позиция, где корпус покидает ленту; ровно одна на ленту |

Правила, которые держит и редактор, и валидатор:

1. место инспекции можно поставить только на позицию — позиция с местом
   инспекции становится инспекционной;
2. если место инспекции на ленте **одно**, оно становится **основным
   автоматически**; при нескольких основное выбирается вручную
   (кнопка «★ Сделать основным», по умолчанию — самое раннее);
3. точка сбросa одна: установка на новую позицию переносит сброс;
4. для линейного пути позиции после сброса недостижимы — это ошибка;
   для циклического (ретур) вход корпуса — позиция сразу за сбросом;
5. имя камеры (роли) — `A-Z 0-9 _`, 2–24 символа с буквы, уникально
   на всю ленту;
6. лента: от 2 до 64 позиций.

Панель «ПРОВЕРКА КОНФИГУРАЦИИ» показывает ошибки и предупреждения;
клик по нарушению выделяет виновную позицию. Кнопка «▶ Пройти путь»
проигрывает маршрут корпуса по собранной ленте — проверка, что лента
собрана так, как задумано.

## Формат `belt.path.v1`

`belt_path.json` — контракт между редактором и будущей универсальной
системой. Пишется и проверяется одинаково с двух сторон:
`js/model.js` (браузер) и `belt_model.py` (валидация сервера и runtime):

```json
{
  "schema": "belt.path.v1",
  "name": "7-камерная линия (текущая)",
  "path_type": "linear",
  "positions": [
    {
      "label": "ВХОД · НАЛИЧИЕ",
      "inspection": { "cameras": ["INPUT_LEFT", "INPUT_RIGHT"], "primary": true },
      "reset": false
    },
    { "label": "ТРАНСПОРТ", "inspection": null, "reset": false }
  ]
}
```

`path_type`: `linear` — вход на позиции 0, корпус идёт до сброса;
`loop` — ретур, вход сразу за сбросом, полный оборот ленты.

В папке есть пресет-файл `belt_path.json` — текущая 7-камерная линия,
собранная вручную: инспекция `+0` (2 камеры, основное место — наличие
детали), инспекция `+4` (SPIDER ×4 + TOP), позиция `+7` под распределитель
и сброс на `+8`. Тот же результат собирается за секунды из выпадающего
списка «Заготовка» в редакторе.

## Файлы

```text
belt_editor/
├── index.html          экран редактора
├── css/belt-editor.css тёмная HMI-тема (токены как в HMI линии)
├── js/model.js         модель ленты, инварианты, валидация, пресеты
├── js/editor.js        рендер и взаимодействия
├── belt_model.py       Python-контракт belt.path.v1 (сервер + будущий runtime)
├── serve.py            статика + api/belt, только stdlib
├── belt_path.json      сохраняемая конфигурация (сейчас — текущая линия)
├── run_belt_editor.bat запуск на Windows
└── tests/              контракт модели (pytest)
```

## Тесты

```bat
python -m pytest belt_editor/tests
```
