# ConveyerThree — трёхкамерная линия

Production-версия системы визуальной инспекции и сортировки корпусов для
комплекса с **тремя USB-камерами**. Архитектура, жизненный цикл и
инструментарий приведены к уровню основного (семикамерного) приложения:

- тонкая точка входа `main.py`;
- пакет `application/` — composition root, startup/shutdown, callbacks, UI;
- разбитое на миксины ядро `core/cycle/` и подпакет отчётов
  `core/rule_report/`;
- ленивые импорты пакетов `core` и `domain` (импорт точки входа не тянет
  YOLO/OpenCV);
- режим **РАБОТА** (`CONVEY_MODE=work`): чистый видеопоток без отладочной
  разметки и пауз;
- `NoCacheStaticFiles` — HMI всегда получает свежие HTML/JS/CSS;
- предстартовые и операторские диагностики;
- консольная проверка камер `camera_check.bat`;
- прошивка `firmware/convey15.ino`;
- pytest-набор и dev-зависимости (`requirements-dev.txt`, `setup.cfg`).

Линия направляет корпус в один из каналов:

- `GOOD` — годная деталь;
- `BAD` — брак;
- `CLEANUP` — очистка (стекло на дне / брак сварки — дефекты, требующие
  очистки, как и в трёхкамернике).

## Схема линии

Одна стадия инспекции: все три камеры смотрят на корпус в позиции `+0`
одновременно (как «нулевой слот» буфера в трёхкамернике):

```text
+0  INSPECT     NEAR + MIDDLE + FAR: наличие детали и все дефекты
+3  SORT        подготовка маршрута распределителя
+4  DROP        корпус проходит распределитель и покидает учёт
```

Первый шаг после «ПУСК» выполняется без движения ленты — проверяется корпус,
уже стоящий под камерами. Дальше обычный цикл: подготовка маршрута на `+3`,
шаг ленты (`G3` с подтверждением `I1/I2`), пауза затухания вибрации, захват
стоп-кадров, модели, правила, решение, архив, review.

## Камеры и модели

| Роль    | camera_mapping.json | Модели                                      | Что контролирует                |
| ------- | ------------------- | ------------------------------------------- | ------------------------------- |
| NEAR    | 0                   | `windows_4.pt`, `shells.pt`                 | разновысотность, раковины окон  |
| MIDDLE  | 1                   | `bottom_glass_new_v3.pt`, `welding_new_2.pt`| стекло на дне, брак сварки      |
| FAR     | 2                   | `windows_4.pt`, `shells.pt`                 | разновысотность, раковины окон  |

Файлы весов в репозиторий не входят — смотрите `weights/README.md`.

## Правила инспекции

- `part_presence` (служебное) — наличие детали по окнам на NEAR/FAR;
- `uneven_heights` — разновысотность ячеек окон: вертикальная секущая через
  середину окна, высота в px; брак при `h_max ≥ max`, `h_min ≤ min` или
  разбросе `≥ difference` (пороги раздельно для NEAR и FAR);
- `window_sinks` — раковины в окнах (детекции `shells.pt`);
- `bottom_glass` — стекло на дне (CLEANUP-дефект);
- `welding` — брак сварки (CLEANUP-дефект).

Приоритеты итогового решения (как коды состояний трёхкамерника):
`window_sinks` (100) > `uneven_heights` (99) > `bottom_glass` (80) >
`welding` (70) > годно (1).

## Протокол контроллера

Используется текущий диалект прошивки `firmware/convey15.ino` (тот же, что у
семикамерника): шаг ленты `G3` с подтверждением `I1/I2`, абсолютные
перемещения осей распределителя `G27`, парковка `G28`, плавный/аварийный
стоп `G0`/`G1`. Старый диалект трёхкамерника (`G1/G2`, относительный `G20`
со `shift_point`) не используется — для этой линии нужна прошивка convey15.

## Структура приложения

```text
main.py                  тонкая точка входа (run.bat)
application/             composition root и жизненный цикл
  bootstrap.py           сборка приложения, CONVEY_MODE, проверка маппинга
  factory.py             создание камер, vision, инспекции, оборудования, цикла
  startup.py             последовательность инициализации и прогрева камер
  shutdown.py            детерминированное завершение и освобождение ресурсов
  callbacks.py           EXIT (штатный/форсированный) и редактор порогов
  lifecycle.py           связка startup/UI/shutdown
  runtime.py             разделяемое между стадиями состояние
  status.py              начальный снимок статуса линии для HMI
  ui.py                  запуск pywebview и сигналы
  constants.py           тайм-ауты жизненного цикла
core/
  cycle/                 ProductionCycle, разложенный по миксинам
    orchestrator.py      пуск/стоп, главный цикл, авария
    step.py              фазы шага и единственная стадия INSPECT
    diagnostics.py       предстартовые и операторские проверки
    jog.py               ручной ход
    status.py            телеметрия, анализ кадра, публикация в HMI
  rule_report/           сборка строк отчёта по правилам
  decision_engine.py     оркестратор правил
  live_preview.py        живой просмотр камер
  state_machine.py       состояния линии
  step_stages.py         фазы шага и передача камер
domain/                  Part, правила дефектов, геометрия, загрузчик порогов
```

## Запуск

Требования: Windows, Python 3.11, зависимости из `requirements.txt`
(для разработки/тестов — дополнительно `requirements-dev.txt`).

```bat
setup.bat
run.bat
```

- `run.bat` — production-режим (HMI в pywebview + реальное железо по COM);
- `run_work.bat` — режим **РАБОТА** (`CONVEY_MODE=work`): чистый поток без
  разметки и отладочных пауз;
- `run_camera_calibration.bat` — консольная калибровка камер
  (`camera_mapping.json` + `calibration.json`);
- `camera_check.bat` — консольная диагностика USB-камер без запуска линии;
- `python ui_simulation.py` — прогон HMI без оборудования (симуляция ленты,
  распределителя и камер) для проверки интерфейса.

## Разработка и тесты

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest
```

Статические проверки:

```bat
.venv\Scripts\python.exe -m pyflakes application config core domain hardware inspection vision tests
.venv\Scripts\python.exe -m pycodestyle application config core domain hardware inspection vision tests
```

## Конфигурация

- `camera_mapping.json` — привязка ролей NEAR/MIDDLE/FAR к индексам камер;
- `thresholds.json` — пороги правил по секциям `NEAR`/`MIDDLE`/`FAR` +
  `disabled_rules`;
- `calibration.json` — механика (шаги, скорости, позиции распределителя,
  `drop_time`); по умолчанию повторяет семикамерник
  (DIST1: GOOD 0 / BAD 340, DIST2: BAD 0 / CLEANUP 340);
- `archive_config.json` — параметры архива (путь, качество JPEG, сжатие при
  выходе).

> [!CAUTION]
> Программа управляет реальной механикой. Перед запуском должны быть доступны
> независимый аварийный останов, исправные концевики и безопасная зона вокруг
> ленты и распределителя.
