# ConveyerThree — трёхкамерная линия

Отдельная версия системы визуальной инспекции и сортировки корпусов для
комплекса с **тремя USB-камерами**. Построена на базе семикамерного проекта
(`ConveyerSeven` в корне репозитория): перенесены логика движения конвейера,
управление камерами и распределителем, правила дефектов и подключение
нейросетей трёхкамерника (`transporter/`), а интерфейс адаптирован под три
камеры и одну позицию инспекции.

Линия направляет корпус в один из каналов:

- `GOOD` — годная деталь;
- `BAD` — брак;
- `CLEANUP` — очистка (стекло на дне / брак сварки — дефекты, требующие
  очистки, как и в трёхкамернике).

## Схема линии

Одна стадия инспекции: все три камеры смотрят на корпус в позиции `+0`
одновременно (как «нулевой слот» буфера в трёхкамернике):

```text
+0  INSPECT     NEAR + MIDDLE + FAR: наличие детали и все дефекты
+3  SORT        подготовка маршрута распределителя
+4  DROP        корпус проходит распределитель и покидает учёт
```

Первый шаг после «ПУСК» выполняется без движения ленты — проверяется корпус,
уже стоящий под камерами. Дальше обычный цикл: подготовка маршрута на `+3`,
шаг ленты (`G3` с подтверждением `I1/I2`), пауза затухания вибрации, захват
стоп-кадров, модели, правила, решение, архив, review.

## Камеры и модели

| Роль    | Индекс (camera_mapping.json) | Модели                                   | Что контролирует                |
| ------- | ---------------------------- | ---------------------------------------- | ------------------------------- |
| NEAR    | 0                            | `windows_4.pt`, `shells.pt`              | разновысотность, раковины окон  |
| MIDDLE  | 1                            | `bottom_glass_new_v3.pt`, `welding_new_2.pt` | стекло на дне, брак сварки  |
| FAR     | 2                            | `windows_4.pt`, `shells.pt`              | разновысотность, раковины окон  |

Файлы весов в репозиторий не входят — смотрите `weights/README.md`.

## Правила инспекции

- `part_presence` (служебное) — наличие детали по окнам на NEAR/FAR;
- `uneven_heights` — разновысотность ячеек окон: вертикальная секущая через
  середину окна, высота в px; брак при `h_max ≥ max`, `h_min ≤ min` или
  разбросе `≥ difference` (пороги раздельно для NEAR и FAR);
- `window_sinks` — раковины в окнах (детекции `shells.pt`);
- `bottom_glass` — стекло на дне (CLEANUP-дефект);
- `welding` — брак сварки (CLEANUP-дефект).

Приоритеты итогового решения (как коды состояний трёхкамерника):
`window_sinks` (100) > `uneven_heights` (99) > `bottom_glass` (80) >
`welding` (70) > годно (1).

## Протокол контроллера

Используется текущий диалект прошивки `firmware/convey15.ino` (тот же, что у
семикамерника): шаг ленты `G3` с подтверждением `I1/I2`, абсолютные перемещения
осей распределителя `G27`, парковка `G28`, плавный/аварийный стоп `G0`/`G1`.
Старый диалект трёхкамерника (`G1/G2`, относительный `G20` со `shift_point`)
не используется — для этой линии нужна прошивка convey15.

## Запуск

Требования и установка совпадают с корневым проектом (Windows, Python 3.11,
зависимости из `requirements.txt`):

```bat
setup.bat
run.bat
```

- `run.bat` — production-режим (HMI в pywebview + реальное железо по COM-порту);
- `run_camera_calibration.bat` — консольная калибровка камер
  (`camera_mapping.json` + `calibration.json`);
- `python ui_simulation.py` — прогон HMI без оборудования (симуляция ленты,
  распределителя и камер) для проверки интерфейса.

## Конфигурация

- `camera_mapping.json` — привязка ролей NEAR/MIDDLE/FAR к индексам камер;
- `thresholds.json` — пороги правил по секциям `NEAR`/`MIDDLE`/`FAR` +
  `disabled_rules`;
- `calibration.json` — механика (шаги, скорости, позиции распределителя);
  по умолчанию повторяет семикамерник (DIST1: GOOD 0 / BAD 340,
  DIST2: BAD 0 / CLEANUP 340);
- `archive_config.json` — параметры архива.

### Тайминги такта

Калибровка таймингов общая с семикамерником (файлы идентичны), подробное
описание — в корневом `README.md`, раздел «Производительность такта».
Кратко о неочевидном:

- `conveyor_speed` при `conveyor_accel < ~15000` **не достигается**: профиль
  движения треугольный, длительность хода задаёт только ускорение;
- `stage_trace_time` — отладочная пауза, срабатывает 5 раз за шаг (на каждом
  переходе фаз), в production должна быть `0`;
- `inter_move_pause_ms` отправляется как `G9`; без неё действует прошивочный
  дефолт 2000 мс, добавлявший 2 с к каждому шагу;
- `move_start_delay` — защита от гонки опроса `I1/I2` после `G3`, ноль запрещён.

> [!CAUTION]
> `settle_time`, `drop_time` и `conveyor_accel` зависят от физики стенда.
> Слишком малый `settle_time` размывает кадр и ломает пиксельный замер высоты
> ячеек в `uneven_heights` (пороги 20–47 px). Подбирайте на стенде.

## Отличия от семикамерной версии

1. Одна стадия инспекции вместо двух (`INPUT` + `SPIDER/TOP` → `INSPECT` на
   позиции `+0`); сортировка на `+3`, сброс на `+4` вместо `+7`/`+8`.
2. Три роли камер вместо семи; нейросети и правила перенесены из
   трёхкамерника `transporter/` (2 модели на боковые камеры, 2 на центральную).
3. Алгоритм разновысотности окон перенесён из трёхкамерника с исходными
   порогами (NEAR: 20/42/11 px, FAR: 21/47/11 px, зазор пересечений 7 px).
4. Интерфейс адаптирован: три превью камер, шкала линии из пяти позиций
   (`+0 … +4`), фазы `INSPECT_*` в мониторе процесса, панель порогов и анализ
   кадра работают с пятью правилами трёхкамерника.
5. Исправлены замеченные в `transporter/` ошибки: убрано всегда-истинное
   условие вида `if camera_index == 0 or 2`, мёртвый `arduino_controller.py`
   и жёстко прописанные пути; вся конфигурация — через JSON-файлы.

> [!CAUTION]
> Программа управляет реальной механикой. Перед запуском должны быть доступны
> независимый аварийный останов, исправные концевики и безопасная зона вокруг
> ленты и распределителя.
